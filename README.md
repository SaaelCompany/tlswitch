# tlswitch

Шлюз для Windows-сервера: сотрудники открывают государственные сайты обычным браузером. Сертификаты Минцифры и TLS ставятся только на сервер. На компьютеры пользователей ничего ставить не нужно.

Проверка сертификата сайта не отключается. Шлюз доверяет системным корневым сертификатам и публичным сертификатам Russian Trusted CA с портала Госуслуг. Сайт с чужим или просроченным сертификатом не откроется.

## Что выбрать на главной странице

**На сервере.** На Windows запускается Chrome или Edge. Он сам устанавливает TLS с сайтом, в том числе с сайтами на сертификате Минцифры. Пользователь видит экран этого браузера в своём и может войти: адрес для сайта остаётся настоящим, поэтому возврат из ЕСИА попадает обратно в ту же сессию. Нужен установленный на сервере Chrome или Edge.

**Через прокси.** Сервер сам скачивает страницу по HTTPS и отдаёт её браузеру пользователя по обычному HTTP. Это легче, отдельный браузер на сервере не нужен. Сложный вход через ЕСИА так обычно не заканчивается: после входа сайт возвращает браузер на `https://www.gosuslugi.ru`, уже мимо шлюза.

На сборке проверено, что режим «На сервере» рисует главную Госуслуг и по кнопке «Войти» открывает `https://esia.gosuslugi.ru/login`. Форма ЕСИА появляется, когда сайт отдаёт свои скрипты. С части адресов дата-центров он вместо скрипта возвращает HTML-заглушку, и форма остаётся пустой: это ответ самого сайта, не отключение проверки сертификата.

## Чего программа не делает

Сайты, которые говорят только по ГОСТ-TLS (КриптоПро, «Кузнечик», «Магма»), этим шлюзом не открыть. Обычный TLS 1.2 и TLS 1.3 с российским сертификатом — открываются. Список сайтов ограничен суффиксами из конфигурации: это не открытый прокси в весь интернет.

## Установка на Windows

Нужен Go 1.22 или новее.

```powershell
go build -o tlswitch.exe .\cmd\tlswitch
```

Положите рядом `tlswitch.exe` и `tlswitch.yaml`. Установите Google Chrome или Microsoft Edge, если нужен режим «На сервере».

От администратора:

```powershell
.\tlswitch.exe install
.\tlswitch.exe start
```

Остановка и удаление службы: `.\tlswitch.exe stop`, `.\tlswitch.exe uninstall`.

Без службы, для проверки: `.\tlswitch.exe -config C:\tlswitch\tlswitch.yaml`.

Откройте порт в брандмауэре:

```powershell
netsh advfirewall firewall add rule name="tlswitch" dir=in action=allow protocol=TCP localport=8080
```

Проброс на роутере или NAT: внешний TCP-порт на `IP-сервера:8080`. Пользователи открывают `http://IP-или-имя:8080`.

Если этот адрес доступен из интернета, задайте `auth_user` и `auth_password`. Лучше ещё выпустить обычный сертификат на ваше имя (не Минцифры) и заполнить `tls_listen`, `tls_cert`, `tls_key`: иначе всё, что человек вводит, включая пароль ЕСИА в режиме «На сервере», идёт по сети открытым текстом.

## Внутренний DNS

Необязательно. Если во внутренней DNS `www.gosuslugi.ru` и остальные нужные имена указывают на этот сервер, их можно открывать как `http://www.gosuslugi.ru`. Шлюз сам резолвит настоящий адрес сайта через DNS из `upstream.dns`, поэтому не зацикливается на себя. В этом режиме из ответа убирается HSTS, иначе браузер больше не согласится на HTTP.

## Сертификаты

В программу уже встроены сертификаты с `gu-st.ru` (тот же набор, что раздаёт Госуслуги):

| Russian Trusted Sub CA (2022) | `BBBDE2103E790B999EC62BD03CF625A5A2E7C316E10AFE6A490EEDEAD8B3FD9B` |
| Russian Trusted Sub CA (2024) | `2155785036C900DBB5F1BB2A1569C80C55595BD6BF94867A29BBDDBC7D88A3F2` |

Дополнительные PEM можно указать в `upstream.ca_file`. Для режима «На сервере» эти же сертификаты один раз записываются в политику Chrome и Edge **учётной записи, под которой запущена служба**, а не на компьютеры сотрудников. На Linux для этого нужны права на `/etc/opt/chrome/policies/managed`.

## Конфигурация

`browser.no_sandbox: true` нужен, только если Chrome сразу закрывается (часто у службы без интерактивного рабочего стола). `browser.max_sessions` ограничивает число одновременных окон: каждое — отдельный Chrome. Сессия без действий закрывается через `browser.idle_timeout`, временный профиль удаляется. Нажатия и пароли в журнал не пишутся. В журнале остаются метод, имя сайта, путь без параметров запроса и код ответа.

`allow_suffixes` — какие имена вообще можно открыть. Чужой адрес получит отказ и снаружи, и из браузера на сервере.
