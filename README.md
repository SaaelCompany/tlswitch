# tlswitch

Шлюз для Windows-сервера: сотрудники открывают государственные сайты обычным браузером. Сертификаты Минцифры и TLS ставятся только на сервер. На компьютеры пользователей ничего ставить не нужно.

Проверка сертификата сайта не отключается. Шлюз доверяет системным корневым сертификатам и публичным сертификатам Russian Trusted CA с портала Госуслуг. Сайт с чужим или просроченным сертификатом не откроется.

## Что выбрать на главной странице

**На сервере.** На Windows запускается Chrome или Edge. Он сам устанавливает TLS с сайтом, в том числе с сайтами на сертификате Минцифры. Пользователь видит экран этого браузера в своём и может войти: адрес для сайта остаётся настоящим, поэтому возврат из ЕСИА попадает обратно в ту же сессию. Нужен установленный на сервере Chrome или Edge.

**Через прокси.** Сервер сам скачивает страницу по HTTPS и отдаёт её браузеру пользователя по обычному HTTP. Это легче, отдельный браузер на сервере не нужен. Сложный вход через ЕСИА так обычно не заканчивается: после входа сайт возвращает браузер на `https://www.gosuslugi.ru`, уже мимо шлюза.

На сборке проверено, что режим «На сервере» рисует главную Госуслуг и по кнопке «Войти» открывает `https://esia.gosuslugi.ru/login`. Форма ЕСИА появляется, когда сайт отдаёт свои скрипты. С части адресов дата-центров он вместо скрипта возвращает HTML-заглушку, и форма остаётся пустой: это ответ самого сайта, не отключение проверки сертификата.

## Чего программа не делает

Обычный TLS 1.2 и TLS 1.3 с российским сертификатом открываются. Если сайт говорит только шифром `TLS_GOSTR341112_256_WITH_28147_CNT_IMIT`, шлюз поднимает этот ГОСТ на сервере: на компьютеры пользователей сертификат Минцифры ставить не нужно. Шифры «Кузнечик» и «Магма» (CTR_OMAC) по-прежнему не поддерживаются.

Сайт, который требует клиентский сертификат пользователя, так не открыть. `gisoms.ffoms.gov.ru` именно такой: обычный HTTP ничего не отвечает, ГОСТ-сервер обрывает рукопожатие без сертификата клиента (`alert 40`), а самоподписанный сертификат отклоняет как неизвестный УЦ (`alert 48`). Список сайтов ограничен суффиксами из конфигурации: это не открытый прокси в весь интернет.

## Установка на Windows

Готовый файл для 64-битной Windows — `tlswitch.exe` в корне этого репозитория. Рядом с ним лежит `tlswitch.yaml`. Скопируйте оба в одну папку, например `C:\tlswitch`. Установите Google Chrome или Microsoft Edge, если нужен режим «На сервере».

Собрать заново (нужен Go 1.22 или новее), находясь в каталоге с исходниками:

```powershell
go build -o tlswitch.exe .\cmd\tlswitch
```

От администратора:

```powershell
.\tlswitch.exe install
.\tlswitch.exe start
```

Остановка и удаление службы: `.\tlswitch.exe stop`, `.\tlswitch.exe uninstall`. После замены `tlswitch.exe` выполните `.\tlswitch.exe restart`.

Служба работает от системной учётной записи. Политика сертификатов Chrome и Edge пишется в раздел компьютера (`HKLM`), потому что у службы нет профиля пользователя и запись в `HKCU` даёт Access is denied.

Без службы, для проверки: `.\tlswitch.exe -config C:\tlswitch\tlswitch.yaml`.

Откройте порт в брандмауэре:

```powershell
netsh advfirewall firewall add rule name="tlswitch" dir=in action=allow protocol=TCP localport=80
```

Проброс на роутере или NAT: внешний TCP-порт 80 на этот сервер. Пользователи открывают `http://IP-или-имя`. Если порт 80 занят, поменяйте `listen` и открывайте шлюз с портом в адресе; файл hosts тогда не подойдёт, порт в нём не задаётся.

Если этот адрес доступен из интернета, задайте `auth_user` и `auth_password`. Лучше ещё выпустить обычный сертификат на ваше имя (не Минцифры) и заполнить `tls_listen`, `tls_cert`, `tls_key`: иначе всё, что человек вводит, включая пароль ЕСИА в режиме «На сервере», идёт по сети открытым текстом.

## Свой сайт

На стартовой странице шлюза есть форма «Добавить сайт». Туда вписывается точный адрес, например `https://lk.example.ru/cabinet`. В список попадает только это имя хоста, не весь домен и не произвольный прокси. Список хранится в `data/sites.json` рядом с программой и начинает действовать сразу, без перезапуска. Удалить можно только добавленный сайт. Встроенные суффиксы вроде `gosuslugi.ru` форма не снимает.

Вход через ЕСИА открывайте кнопкой «На сервере» или карточкой `https://esia.gosuslugi.ru/login/`. Если страница входа запрашивает свои файлы с корня шлюза (`/__jsch/...`, `/auth/...`), запрос уходит на тот сайт, с которого пришёл, а не отвечает 404.

## Файл hosts

На компьютере пользователя в `C:\Windows\System32\drivers\etc\hosts` пишется адрес сервера и имя сайта, без `http://`:

```
172.17.0.1 gisoms.ffoms.gov.ru
172.17.0.1 www.gosuslugi.ru
```

Дальше в браузере открывают `http://www.gosuslugi.ru`. Строка `172.17.0.1 http://gisoms.ffoms.gov.ru` не работает: в hosts нет схемы, только IP и имя. `https://` тоже не подходит: тогда браузер сам проверяет сертификат и на компьютер пришлось бы ставить сертификат Минцифры.

Шлюз слушает порт 80 и по заголовку `Host` понимает, какой сайт открывать. Имена, на которые ссылается страница, тоже нужно прописать отдельными строками, иначе картинки и переходы уйдут в обычный DNS. Настоящий адрес сайта шлюз берёт из `upstream.dns`, поэтому не зацикливается на себя. Из ответа убирается HSTS, иначе браузер больше не согласится на HTTP.

`http://gisoms.ffoms.gov.ru` при такой строке дойдёт до шлюза, но сам сайт всё равно не откроется: ему нужен клиентский сертификат ГОСТ.

## Сертификаты

В программу уже встроены сертификаты с `gu-st.ru` (тот же набор, что раздаёт Госуслуги):

| Сертификат | SHA-256 |
| --- | --- |
| Russian Trusted Root CA | `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31` |
| Russian Trusted Sub CA (2022) | `BBBDE2103E790B999EC62BD03CF625A5A2E7C316E10AFE6A490EEDEAD8B3FD9B` |
| Russian Trusted Sub CA (2024) | `2155785036C900DBB5F1BB2A1569C80C55595BD6BF94867A29BBDDBC7D88A3F2` |

Дополнительные PEM можно указать в `upstream.ca_file`. Для режима «На сервере» эти же сертификаты один раз записываются в политику Chrome и Edge **учётной записи, под которой запущена служба**, а не на компьютеры сотрудников. На Linux для этого нужны права на `/etc/opt/chrome/policies/managed`.

## Конфигурация

`browser.no_sandbox: true` нужен, только если Chrome сразу закрывается (часто у службы без интерактивного рабочего стола). `browser.max_sessions` ограничивает число одновременных окон: каждое — отдельный Chrome. Сессия без действий закрывается через `browser.idle_timeout`, временный профиль удаляется. Нажатия и пароли в журнал не пишутся. В журнале остаются метод, имя сайта, путь без параметров запроса и код ответа.

`allow_suffixes` — какие имена вообще можно открыть. Чужой адрес получит отказ и снаружи, и из браузера на сервере.

Если задан `upstream.proxy`, запасной ГОСТ-канал не используется: через HTTP-прокси идёт только обычный TLS.

В программу входит библиотека GoGOST (Сергей Матвеев), она распространяется по GPL-3. Собранный с ней `tlswitch` тоже нужно распространять на условиях GPL-3. Текст лицензии лежит в `third_party/gogost/LICENSE.md`.
